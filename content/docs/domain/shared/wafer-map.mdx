## Contract

`WaferMapGallery` is the shared rendering entry point, not the Report Center tab entry
point. It accepts one resolved discriminated input: `cp-final-bin`, `cp-parameter`,
or `defect`. `ReportWaferMap` composes this Gallery for Report Center; DOE App must
not place a Gallery beside a separately reimplemented Report control bar. Every wafer
carries its own geometry and data payload; no fixture or component assumes that 25
wafers share values.

Final Bin presentation preserves the BFF bin label and supplied `die.pass` literally.
Explicit Pass uses a green colour family; explicit Fail uses a contrasting warm
colour family, with stable bin-specific shades. Neither numeric Bin `1`, a label,
nor a colour hash can override `die.pass`. The legacy input palette is a fallback
only when CP status is absent; the Final Bin schema requires that status. Thumbnail,
fullscreen and legend use the same resolver. Mixed-state bins show both swatches;
supplied inspection counts and summary facts remain unchanged.

All modes share a neutral grey legal-die base. Defect types use saturated contrasting
colours so selected defects remain visible against the base. Parameter legends in
the gallery and fullscreen show the supplied `scale.domainMin` / `domainMax` and unit,
using the same continuous value-to-colour function as the map. Grey means no valid
value; red outlines denote only explicitly supplied CP Fail. The component never
computes a new range, interprets the range as specification, or invents OOS cutoffs.

`WaferMapCore` owns three stacked Canvas layers: an immediate base layer for all legal dies, a data layer for Final Bin / parameter / defect color, and an interaction layer. The shallow grey circular boundary is presentation only; the supplied legal-die coordinates define the actual footprint.

CP geometry (`CP_DIE_GRID_V1`) and defect geometry (`DEFECT_INDEX_V1`) are independent coordinate contracts. This component deliberately does not infer an overlay between them.

Defect gallery uses single-select, searchable Combobox controls for `Layer` and `Defect Type`. `All Defect Type` serializes to an empty type filter, which means all defect types on the selected Layer.

Hover uses Canvas hit testing and one document portal tooltip, so a 4,099-die wafer never creates 4,099 React nodes. The tooltip currently shows wafer, DIE_X, DIE_Y, Final Bin and, where relevant, parameter value/validity or defect count.

每片 wafer 卡片提供 `全屏查看` 入口。放大层复用同一个 Canvas renderer，并拥有局部
Die 选择、80%–140% 缩放和前后 wafer 浏览。单片 Parameter / Layer / Defect Type 选择只发出 callback intent，由 consumer 查询并注入新数据。右侧先展示
当前 Die 明细，再展示由输入合同提供的 wafer 统计表。三种视图分别使用 Final Bin、
单片 Parameter 的 SPEC、样本数、Mean、Std. Dev.、Min、Max、Median、CPK 和按 Layer 的 Defect Type 统计，组件不会从缺失字段推断这些业务事实。

## Schema

```ts
export const waferMapDieSchema = z.object({
	id: z.string(),
	x: z.number().finite(),
	y: z.number().finite(),
})

export const waferMapBoundsSchema = z.object({
	minX: z.number().finite(),
	maxX: z.number().finite(),
	minY: z.number().finite(),
	maxY: z.number().finite(),
})

export const waferMapDataSchema = z.object({
	id: z.string(),
	dies: z.array(waferMapDieSchema),
	bounds: waferMapBoundsSchema,
})
```

可放大 wafer 的 expected schema 还要求 mode-specific `inspection`：

```ts
type FinalBinInspection = {
  testedDieCount: number
  totalFailBinCount: number
  totalFailBinRatePercent: number
  rows: Array<{ binCode: string; binDescription: string; count: number; ratePercent: number }>
}

type ParameterInspection = {
  sampleCount: number | null
  mean: number | null
  stddev: number | null
  min: number | null
  max: number | null
  median: number | null
  cpk: number | null
  cpkStatus: string
  lsl: number | null
  usl: number | null
  unit: string | null
}

type DefectInspection = {
  byLayer: Array<{
    layerId: string
    defectDieCount: number
    defectRecordCount: number
    inGridRecordCount?: number
    outsideGridCount?: number
    classBreakdownStatus?: "AVAILABLE" | "UNAVAILABLE"
    rows: Array<{ typeId: string; label: string; nameResolved?: boolean; count: number; ratePercent: number }>
  }>
}
```

The gallery input extends this geometry with rendering-specific die metadata. The component owns the local expanded inspection view, but owns no data fetch, parameter percentile calculation, defect/statistics aggregation, or routing; those belong to the consuming app/BFF.

## Consumer missing-map presentation

`WaferMapGallery.renderMissingMap(state)` optionally supplies the body of an
explicitly empty or unavailable map slot. ReportWaferMap uses ReportState with
the source reason and 160px minimum height. Available/partial map rendering,
summary facts, standalone gallery fallbacks and data semantics remain intact.

## Single-wafer inspection contract · 2026-10-11

Statistics are supplied full-population facts, independent of visible point filters.
CPK displays two decimals, including negative values; missing SPEC sides display `—`
without inferring a bound from the color scale. Parameter sample count is distinct
from CP Tested Die. Uniformity / Hi-Lo / Particle Rate and images remain outside this slice.

Selected-layer Defect dies can carry `defectCount`, `classBreakdown` and
`classBreakdownStatus` separately from `defects[]` actual records. Aggregates carry
stable `typeId`, supplied label, count and optional `nameResolved`; unresolved
categories retain their numeric identity. Empty `defects[]` does not erase an
authoritative aggregate count. No synthetic Defect ID or image is generated.
Full inspection record totals include outside-grid records; type filters only
change map presentation, never the statistics denominator. Unavailable class
details display “分类明细未提供” rather than zero records.

`expandedWaferId` and `onExpandedWaferChange` optionally make physical-wafer
inspection intent controlled. New parameter/layer map identities reopen that
same wafer; React map keys still use `mapId`. Consumer owns pending/failure data
state and must retain inspection intent during queries.

## Parameter Map same-test CP summary · WM02 (2026-10-11)

Each Parameter wafer optionally accepts `cpSummary`, distinct from both
`inspection.sampleCount` (parameter-valid measurements) and legacy `summary`
(selected CP slice totals):

```ts
type ParameterCpSummary = {
  status: "AVAILABLE" | "UNAVAILABLE"
  testedDieCount: number | null
  passDieCount: number | null
  failDieCount: number | null
  passRatePercent: number | null
  failRatePercent: number | null
  unavailableReason?: string
}
```

The expanded Parameter panel labels these as `CP Tested Die Count`, `CP Pass`,
`CP Fail`, `CP Pass Rate`, `CP Fail Rate`; the parameter population is labelled
“参数有效样本数”. CP rates are Backend facts formatted to two decimals, never
calculated in UI. Missing or unavailable same-test facts display `—` plus the
source reason; neither valid N nor legacy summary fills them. Zero tested Die
with null rates preserves null percentages. Delivered CP facts remain visible
when parameter statistics are absent. Legacy modal totals remain explicitly
labelled “所选 CP slice 汇总”.

## Parameter variation · WM03 / WM04 (2026-10-11)

The user approved the prototype definitions: `Uniformity (RsU)` is sample
standard deviation / mean × 100%; `Hi/Lo Var.` is (raw max − raw min) /
(2 × mean) × 100%. Backend Domain computes these on the same full
`PHYSICAL_VALID` population used by per-wafer Mean / Std. Dev. / Min / Max.
UI inspection adds optional nullable `uniformityPercent` and
`hiLoVariationPercent`, only formatting supplied percentages to two decimals.
Negative results remain negative; zero mean, missing input or nonfinite result
stay unavailable (`—`), with no absolute-value transform or clamping.

## Actual defect records · WM06 (2026-10-11)

Each Defect Die may provide `defectRecordsStatus` (`AVAILABLE` / `UNAVAILABLE`)
and actual `defects[]` record IDs. Records retain `classNumber`, `sizeX`, `sizeY`,
`waferX`, `waferY`, `imageCount` as optional nullable facts. Selecting an ID
locally expands that record's supplied dimensions, coordinates and class; it
issues no query and attaches no image action. No unverified physical unit is
assumed. Missing record delivery shows “逐条记录未提供”; aggregate counts remain
unchanged. Mock IDs and values in `defectAggregates` are UI fixtures only.

## Independent default-layer CP defect summary · WM08 (2026-10-11)

Both CP wafer contracts optionally accept `defectSummary` with `status`
(`AVAILABLE` / `EMPTY` / `UNAVAILABLE`), `layerId`, nullable `defectDieCount`
and optional `unavailableReason`. Cards show `Defect Die · Layer {layerId}`;
available zero remains zero, while EMPTY / UNAVAILABLE show `—` and source
reason. An absent summary adds no metric. This observation is independent of
CP geometry, has no overlay/join implication and never falls back to CP totals.
