## Purpose

这页记录当前项目里设计、创建 DOE 领域组件的标准流程。它来自提交历史、上游输入记录、ADR、设计系统文档和现有组件结构，用作后续开发和 AI Coding 的参考。

它不是单个业务需求，也不是原型截图的直接转写。真正新增组件时，必须先建立或更新对应 `docs/upstream/components/NNN-component-slug/` 记录，再进入 ADR、组件合同和实现；重构已有组件时，应先阅读对应 upstream 记录，并在实现后同步组件合同或 post-intake notes。

## SOP

1. 建立上游输入记录。

   `docs/upstream/components/NNN-component-slug/` 是创建领域组件的起点规范。无论输入来自用户对话、截图、原型观察，还是 AI 生成的初步分析，都必须先落到这个目录结构里，再进入组件设计和实现。

   目录至少包含 `README.md` 和源截图或来源说明。`README.md` 记录输入来源、用户原话、可见 UI 区域、候选领域边界、open questions。AI 可以辅助整理，但不能绕过这一步直接创建领域组件。

2. 提炼组件边界。

   从 upstream 中判断组件负责什么、不负责什么、哪些只是 candidate。截图和原型是证据，不是直接实现指令。

3. 确认组件文件包。

   组件按 docs 分类放置在 `trial`、`shared`、`report` 等目录下，文件结构采用：

   ```text
   src/components/domain/<component>.tsx
   src/components/domain/<component>.fixtures.ts
   src/components/domain/<component>.scenarios.ts
   src/schemas/domain-component-inputs.ts
   content/docs/domain/<category>/<component>.mdx
   ```

4. 定义 UI-facing schema。

   schema 放在 `src/schemas/domain-component-inputs.ts`，导出 Zod schema 和 TypeScript type。它是 UI 入参契约，不是 backend、MES、Oracle 或 Gateway DTO。

5. 准备 fixtures 和 scenarios。

   demo/test 数据放进 fixtures 和 scenarios，不写死在组件渲染逻辑里。按组件需要覆盖 normal、empty、loading、partial、error、readonly、large-data 等状态。来自原型的真实转录数据应标记为 prototype-backed；不要把它描述成生产系统真相源。

6. 实现领域组件。

   组件通过 props 接收 schema-shaped input，通过 callback 暴露交互意图。组件可以拥有局部展示状态，但不能拥有应用 workflow；会改变业务数据集或跨组件联动的过滤/选择应由外部业务状态持有。

7. 拆分复杂模型。

   当组件包含复杂布局、坐标、渲染、映射或策略逻辑时，拆出 `<component>-model.ts`，并让组件只负责组合和呈现。

8. 编写 MDX 预览。

   领域组件文档至少保留 `预览 / Preview` 和 `Contract`。`Shadcn Components`、`Schema`、`Scenarios` 可按组件复杂度补充。预览应导入组件和 scenarios，不在 MDX 中重写大段 mock 数据。

9. 更新公共出口。

   通过 `src/components/domain/index.ts` 暴露稳定组件 API。不要让应用项目依赖内部 helper、fixtures、scenarios 或 foundation UI wrapper。

10. 验证。

   先跑 targeted lint/typecheck 和相关测试。交互或布局变化需要浏览器验证关键路径。完成后跑一次 full build。

## Development Constraints

1. 这个仓库是 DOE Domain UI asset library，不是 DOE 应用。
2. 领域组件不能直接调用 `fetch`、App Service、Gateway、MES、Oracle 或真实提交函数。
3. 应用 workflow、页面路由、跨组件状态机、真实提交、重试和轮询属于应用工程。
4. 领域组件只能拥有局部展示状态，例如展开、展示模式、表格局部排序、局部校验。过滤或选择若会改变注入数据集、触发跨组件联动或请求 backend，则属于外部业务状态。
5. 基础 UI 必须组合 `src/components/ui` 的 shadcn primitive，不自建 Button、Input、Select、Dialog、Table、Tabs、Badge、Switch、Tooltip、Card 或 Dropdown Menu 替代体系。
6. 业务尺寸走 `.domain-ui-typography`、`src/app/globals.css` 中的 DOE density tokens 和 `docs/practices/domain-ui-sizing.md`。
7. 不要把 `NO_DATA`、`N/A` 或 missing values 转换成 `0`。
8. Planned Condition 不能展示成 Actual Condition。
9. Observed Wafer Scope 不能默认解释成 planned、released、executed 或 completed wafer scope。
10. Candidate Step Mapping 不能展示成 confirmed DOE Step mapping。
11. Mock、derived、deterministic-template、source-provisional data 必须显式标记，不能伪装成 real production fact。
12. Coverage Unknown 不能展示成 pass、no issue 或 defect-free。
