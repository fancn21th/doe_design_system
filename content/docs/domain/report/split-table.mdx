## Contract

`ReportSplitTable` 是只读 report snapshot，不负责编辑 split、recipe 或 MES release。
组件由过滤区域和逐 wafer 的 Split Table 组成；
过滤区域使用多选 Combobox 按 `stageOptions` / `stepOptions` 过滤，空选中表示 `全部`。
当 consumer 提供 `stepFacets` 时，Step 选项和已选 chip 会显示 BFF 提供的
`sourceCount facts / displayCount displayed`；前者是权威 assignment 事实数，后者是
已注入 `rows` 的 active display 数。组件只用 `rows` 执行本地筛选，不会从表格行重新推导
或覆盖 facet count。

表格按 `Stage + Step + Seq` 形成对照组并合并首列。每组先展示 Baseline，再按不同
`condition` 的首次出现顺序生成 `split-1`、`split-2` 等标签；同一 condition 的多个
Wafer 共享同一个 split 标签。表格投影固定为 `Stage / Step / Seq`、`Wafer ID`、
`Recipe`、`Condition`、`Yield` 与 `Top Fail` 六列。

`Top Fail` 直接消费 report snapshot 注入的 CP 参数与数量。`topFails` 有值时可展示
多个 `CP Parameter · Count`；未提供时兼容单值 `topFail` / `topFailCount`。组件不从
raw die data 推算阈值或 Top Fail，也不推断实际工艺事实。

`Yield` 为 nullable snapshot fact：数字 `0` 表示真实的 `0.00%`，`null` 表示上游没有
可用 Yield 证据并显示 `Unavailable`。组件不会把缺失值转换为零；缺失值使用 neutral
视觉语义，也不参与 Yield 阈值分级。

过滤区使用无外框的紧凑控制行，只保留控件自身边界；表格保持自己的单层中性边界
与浅色结构表头。较宽的业务投影通过组件自身的横向滚动容器展示，不能撑破 MDX
预览壳。

本轮表格组合参考本地原型 `DOE Workbench 单文件版.html` 的 `renderSplit`：只迁入
分组、Baseline-first、condition split 标签和多 CP Top Fail 展示；跨 Tab 导航仍由
App 通过 callback 承接。

## Consumer Schema

```ts
type ReportSplitTableInput = {
  stageOptions?: string[]
  stepOptions?: string[]
  stepFacets?: Array<{
    step: string
    stepSequence?: number
    sourceCount: number
    displayCount: number
  }>
  selectedStages?: string[]
  selectedSteps?: string[]
  rows?: ReportSplitTableRow[]
}
```

参考来源为本地 DOE Workbench 单文件版源码和用户提供的目标截图。详细证据与交互规则见
`docs/upstream/components/011-report-split-table/README.md`。

## Scenarios

- `normal`
- `baseline-after-splits`
- `authoritative-step-facets`
- `unavailable-yield`
- `empty`

## POC consumer handoff

`onWaferSelect(row)` 表达从当前 Assignment 进入 Yield Analysis 的意图；`onTopFailSelect(row)` 表达进入 Final Bin Map 的意图。App 接收完整行以保留 Wafer 和分配上下文；组件不负责 URL 或跨 Tab 工作流。
