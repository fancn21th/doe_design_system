## Contract

CP × Inline 由两个独立消费的 Domain UI 资产组成。`ReportCpInlineCandidates`
负责 generation-fixed Candidate Ranking；`ReportCpInline` 负责当前选中组合的分析证据。

- `Recommended CP × Inline Candidates`：保留消费者提供的 Backend 顺序、筛选结果、
  分页与算法版本；组件不重算 score 或重新排序。
- Candidate Ranking 的 CP、Inline、Level、Direction、Min N 与分页均为受控输入，
  通过 callbacks 表达查询意图。`View fit` 只发出选中组合，不在组件内加载分析。
- Candidate 行的缺失统计值显示为不可用，不补成 `0`。

`ReportCpInline` 是选中组合后的完整 CP × Inline 分析组件：

- `CP x Inline 拟合`：受控的 Step、Inline Parameter 与 CP Parameter 选择。
- `Condition 聚合`：受控的 Baseline / Split Wafer 选择，以及 Inline 与 CP 各自有效 population 的聚合表。
- `拟合与定位`：受控的 Fit Grain、Inline metric、CP aggregation、extreme policy 与 Quadratic candidate；三张结果图分别呈现 CP Median、典型 Min 和典型 Max。
- Linear / Quadratic 曲线、gate、阈值、roots、Control Window 与 provenance 都是上游注入的只读证据。组件不执行回归、求根或窗口推导，也不自动选择主模型。
- Collapse、chart hover 和“拟合结果”详情开关属于组件本地展示状态；所有业务选择通过 callbacks 交给消费者。
- Condition 聚合允许 Inline / CP 使用各自有效 Wafer；Wafer 粒度只消费同片配对 evidence。`PAIRED`、`INLINE_ONLY`、`CP_ONLY` 与 `NO_DATA` 不得合并为一个布尔状态。
- Inline Control Window 标记为 `Source Provisional`，不是 Recipe setpoint、生产指令或 release verdict。
- 宽表和图表在组件内部横向滚动；窄屏时 selector 和证据详情纵向堆叠。

原型数据标记为 `prototype-backed`；configured-spec、coverage-mismatch、gate、partial、empty 和 dense 数据只用于场景验证。

## Scenarios

- `normal`
- `configured-spec`
- `coverage-mismatch`
- `insufficient-levels`
- `partial`
- `empty`
- `dense`

## Consumer Handoff

消费者将 Candidate Ranking 放在选中分析之前，并负责把 `View fit` 的
`experimentGroupId + cpParameter + inlineParameter` 变成下方分析范围。候选筛选/分页与
分析选择是两个独立的数据生命周期。

消费者还负责根据 `ReportCpInline` callbacks 更新受控选择、重新请求或映射证据，并注入
与新选择一致的 rows、fit panels、spec、roots 和 control windows。App routing、滚动定位、
跨组件 workflow、Backend BFF、真实数据关联和统计计算均不属于 Domain UI。
