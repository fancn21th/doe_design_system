## Contract

### Candidates

`ReportCpInlineCandidates` 是独立候选列表。输入 `ReportCpInlineCandidatesInput` 包含
已筛选的当前页 `items`、总数、页码、选项、状态、算法版本与 provenance。

- `recommended`：现有算法保存的 HIGH_TREND / MEDIUM_TREND，且无过滤原因。
- `insufficient`：现有 `INSUFFICIENT_SAMPLE` 记录。
- `filtered`：其余非推荐记录，包括 INLINE_CONSTANT、CP_CONSTANT，以及无过滤原因的 LOW。
- 以上映射由上游/消费者提供；组件不分类、不重算评分、不改变输入顺序。
- 旧评分和推荐分类继续有效；8888 原型的 40% Inline Spread + 35% Spearman + 25% R² **未迁入**。
- Step、CP、Inline、view、精确 `pairedN`、reason 与分页均为受控输入；callbacks 只表达查询意图。
- 分页组合 shadcn Base UI Pagination，按官方 Next.js 用法以 `next/link` 渲染链接；显示当前页、相邻页、首末页及间隔省略号。窄屏允许控件局部换行，不撑宽页面。
- 页码、上一页和下一页只发出 `onPageChange(page)` 查询意图，阻止链接导航并保持页面滚动位置；首末页越界、loading/error 或未提供 callback 时禁用对应链接。
- 切换 view 重置列头 N/原因筛选；消费者重置 page=1，并注入同一查询的 rows 与 total。
- Paired Wafers 表示有效同片配对数 / 实验组分配数；`pairedN` 精确匹配，不代表 Min N。
- 推荐表六列；其他两层五列。原因保留现有算法语义，不伪装成新原型的 LOW_FIT 等原因。
- CP/Inline 点击发出 `onOpenCandidate`；`detailAvailable=false` 保留数据展示并禁用详情入口。
- 候选身份始终是 `experimentGroupId + cpParameter + inlineParameter`；不能只按参数对去重。
  Step / Factor / 实验组在入口 title 中可查看。Rank 是当前上游排序下的分页位置。
- 正向 Spearman 使用绿色、负向使用紫色，符号始终同时展示。缺失值显示 `—`。

### Fit

`ReportCpInlineFit` 独立接收 `ReportCpInlineFitInput`，没有候选查询、Drawer 或业务选择状态。

- Wafer Pair 表包含 Wafer、BSL/SPLIT、Condition、Inline Median、CP Median、CP Min/Max。
  Condition 是分配条件，不冒充实际量测；覆盖状态保持 PAIRED / INLINE_ONLY / CP_ONLY / NO_DATA。
- 三张图分别比较 Inline Median 与 CP Median、CP Min、CP Max；仅消费提供的同片 Wafer 点。
- 模型状态、方程、曲线、R²、RMSE、Residual N、df、每图 Pearson/Spearman、规格与交点均为上游只读证据。
  组件不回归、不求根，也不按 N 或 Condition levels 自行判断拟合可用性。
- Wafer Pair 与 Wafer Scatter & Fits 业务区以标题和 body 组成，内容始终可见；Fit × Spec 交点坐标同样直接呈现，不提供模块收缩/展开。
  每图 Linear/Quadratic 曲线显隐与 hover 仍属于本地展示状态，曲线显隐不移除右侧统计证据。域外交点保留标签，图中只画域内交点。
- 未提供 spec / roots / model 时明确展示不可用；missing 不补零。科学计数法保留完整指数，防止小量级值归零。
- 窄屏图与证据纵向堆叠；表格仅在自身横向滚动，图表随证据列宽调整。
- Condition 聚合、拟合配置选择、Control Window 与 Leave-One-Out Stability 不属于新版 Fit。

### Scoped visual contract

仅 CP × Inline 使用局部语义色：accent / Target 为蓝色 `#0071e3`，Linear 为青色
`#007c78`，Quadratic / 负向 Spearman 为紫色 `#8550dc`，Wafer / 正向 Spearman
为绿色 `#079e68`，LSL / USL 为红色 `#d22f3b`。曲线标签、线型与相关系数符号同时保留，
颜色只区分证据含义，不表示通过、失败或因果关系。上述变量随 Candidates / Fit 根节点消费，
不改全局 shadcn 或文档配色。

### Composition

`ReportCpInline` 组合上述两个组件，接收 `ReportCpInlineInput`：`candidates`、`fit`、
`fitStatus` 和可选 `fitError`，继续暴露候选列表 callbacks。

- 对齐本地 `ui/apps/v4/examples/base/drawer-non-modal.tsx` 的
  `modal={false} disablePointerDismissal swipeDirection="right"`，使用当前仓库 Drawer primitive。
- Drawer 不遮罩/锁定外部交互；外部点击保持打开。关闭按钮或 Escape 关闭；点击另一候选切换内容。
- 打开/关闭和当前点击候选属于组合本地展示状态；消费者收到 `onOpenCandidate` 后提供相应 Fit。
- 新候选的三字段身份必须与 Fit 一致；不匹配时保留等待状态，不把上一候选证据显示给新候选。
- Drawer 宽度使用 DOE Fit inspection token 并受 viewport 限制；内容区域独立纵向滚动。

  upstream-unavailable、upstream-available-small-sample、empty。

其余两条明确标记详情不可用。

kelvinS Wafer 摘要来自 `cp_x_inline.ipynb`；拟合曲线和交点在 fixture 制作时离线计算，
标记 `derived`。QG_QgTOT2 独立 Fit 来自原型转录，标记 `prototype-backed`。
边界与密集分页场景为 `mock`，不代表新增测量或真实推荐。Component Lab 只在预览消费者中
筛选这些有限 fixtures，不在产品组件中加载或计算数据。

## Consumer Handoff

这是旧 CP × Inline 分析合同的替换：消费方应分别采用 Candidates、Fit，或使用组合组件，
迁移旧 Level / Direction / Min N 选择及 Condition 配置输入。

消费者负责同一 snapshot / CP slice 内的查询、三层映射、分页、实验组范围、完整 Wafer 身份、
数据版本一致性和模型证据计算。候选点击后更新 `fitStatus`，加载对应三字段身份的 Fit；
切换候选时清除旧 error 并提供新 loading 状态，失败时注入 `fitError`。

App routing、Backend BFF、真实数据库关联、请求与统计算法都在本仓库之外；
Domain UI 不用原型阈值重新解释旧分类，也不决定小样本是否允许拟合。

### Wafer scatter annotation readability — 2026-10-10

Wafer 标签按屏幕坐标避让并限制在绘图区；引线连接原始散点，极窄时省略标签，
但 tooltip 与 Wafer Pair 保留完整身份。散点、拟合曲线、规格和业务值不移动。

[公开自定义组件文档](https://recharts.github.io/guide/customize/)。


### Fit measured-scale display — 2026-10-10

- 每张图的纵轴仅按注入的 Wafer 散点和当前可见曲线取范围，并留少量边距；切换曲线显隐可以改变显示范围，不改变输入数值。
- 规格值在图例保留；超出纵轴的规格明确标注「纵轴范围外」，不强制扩大纵轴。域外规格和交点仍可在 Fit × Spec 明细查看，不移动到图内，也不代表规格通过。
- 小量级 CP Max 使用足够有效数字，避免 `0.0003000092` 与 `0.000300029` 都显示为 `0.000300`。
- `small-scale-far-spec` 是 mock 坐标/精度回归场景；真实拟合曲线以 App 收到的 Backend 证据验收。
- 原型中的离线派生曲线不代表任何 Backend 版本一定会返回同样的可用状态；Wafer 拟合准入仍由 Backend 决定。

### Navigation hierarchy

导航层级按 [Navigation and business blocks](../../../../docs/patterns/navigation-and-blocks.md) 执行。
Candidates 的 Recommended Candidates / Filtered / Insufficient Sample 是三级视图导航，
复用 `ReportViewNavigation` 的图标 + 文字 line Tabs；沿用 Inline Data 的中性选中态，左对齐并支持局部横向滚动。
切换仍发出受控查询意图并清空 pairedN / reason，不在组件内重新分类、评分或请求。
候选图表的局部语义色不定义导航选中态。

## Candidate Block title

候选分析使用共同 ReportBlock / BlockTitle，保留输入标题及可选副标题，稳定锚点为 `wafer-level-candidate-analysis`；问号说明已保存候选结果及相关性边界。移除旧 CardHeader 与标题下分割线，沿用 Split Table 标题与正文间距。三级导航、筛选、分页与 Fit callback 保持既有合同。

## Candidate Pagination adoption — 2026-10-11

用户批注要求替换 `1 / 413` 分页。采用 [shadcn Base Pagination 的 Next.js 用法](https://ui.shadcn.com/docs/components/base/pagination#nextjs)，本地来源为 `ui/apps/v4/registry/bases/base/ui/pagination.tsx` 和 `registry/styles/style-nova.css` 的 Pagination 部分。同步完整 primitive exports，以本地 Lucide 图标和 nova utilities 替换 registry placeholders；官方 `next/link` 适配保留。页码窗口与受控 callback 属于 Candidates 组合；schema、数据查询、评分和排序合同不变。
