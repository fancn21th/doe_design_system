## Purpose

这页用于启动下一次 DOE 领域组件重构。它的目标不是让人记住流程，而是在新任务开始时提醒提问者先输入哪些信息，帮助 AI Coding 快速对齐原型、目标页面、组件边界、fixture 和交互归属。

## Start Prompt

新任务开始时，优先使用下面的输入模板：

```text
请按 DOE Component Refactor SOP 更新一个组件。

1. 原型 URL：
2. 目标 docs 路由：
3. 组件分区：
4. 使用哪些 shadcn/base 组件：
5. fixture 是否要注入真实数据：
6. 哪些交互属于组件本地状态，哪些是外部业务事件：
```

## Input Checklist

1. 原型 URL

   提供可访问的原型地址，例如本地 HTML、localhost 页面或上游截图记录。AI 需要从这里读取真实结构、字段、表头、选项、默认状态和关键交互。

2. 目标 docs 路由

   提供要更新的组件文档页面，例如 `/docs/domain/report/split-table`。这不是原型 URL，而是 Component Lab / docs 里的目标预览页。AI 会据此定位 `content/docs/...`、业务组件、scenario、fixture、schema 和 public export。

3. 组件分区

   描述组件在视觉和职责上的区块，例如“过滤区域 + Split Table”。分区用于决定组件内部拆分和渲染顺序，不等同于应用页面布局。

4. 使用哪些 shadcn/base 组件

   明确希望复用的 foundation UI，例如 Combobox、Table、Tabs、Dialog、Card、Badge。基础 UI 统一从 `src/components/ui` 组合，不在业务组件里自建另一套控件。

5. fixture 是否要注入真实数据

   说明 fixture 使用真实原型数据、脱敏真实数据，还是说明性 mock。真实数据应进入 fixture/scenario，不写死在组件内部。若数据只是从原型转录或部分补齐，应标记为 prototype-backed，不要伪装成生产真相源。

6. 本地状态与外部业务事件

   区分哪些交互由组件自己维护，例如展开、纯展示 tabs、表格局部排序；哪些由外部业务状态拥有，例如会改变注入数据集的过滤、跨组件选择、跳转、保存、提交、release、请求 backend。过滤不是默认本地状态，需按组件合同确认。

## Execution Flow

1. 定位实际源码和 dev server 对应目录。
2. 检查 `git status --short`，避开无关脏文件。
3. 阅读目标组件、schema、fixture、scenario、MDX 和相关 `src/components/ui`。
4. 对照原型提取真实 UI 区域、字段、选项、默认状态和交互。
5. 明确 read-only / editable / callback intent，以及本地展示状态 / 外部业务状态的边界。
6. 扩展 UI-facing schema，只表达组件入参和本地 intent。
7. 更新 fixture/scenario，让数据从组件外部注入。
8. 复用或补齐 shadcn/base foundation UI wrapper。
9. 实现业务组件：已确认的局部展示状态留在组件内；外部业务状态通过 props 输入和 callbacks 暴露意图，组件不直接改变业务数据集。
10. 更新 MDX contract，说明分区、数据来源、交互归属和 out of scope。
11. 运行 lint、typecheck、相关测试，并用浏览器验证关键交互。

## Split Table Reference

`ReportSplitTable` 的重构可作为参考案例：

- 目标路由：`/docs/domain/report/split-table`
- 原型：`DOE report.html`
- 分区：过滤区域 + Split Table
- 基础 UI：Combobox multiple + Table
- fixture：注入 stage options、step options 和真实 split table rows
- 本地状态：stage/step 过滤
- 外部事件：跳转 wafer map、top fail drilldown 等只属于未来 callback intent，不在组件里直接执行

## Yield Analysis Reference

`ReportYieldAnalysis` 的重构补充了一个反例：同样有 Stage / Step 过滤 UI，但过滤结果由外部业务状态注入，组件内部不筛选 `wafers`、`matrixRows`、`lossYieldRows` 或 `conditionYieldRows`。

- 目标路由：`/docs/domain/report/yield-analysis`
- 原型：`DOE report.html` 的 `Yield Analysis` tab
- 分区：过滤区域 + Wafer Yield Ranking + Yield Detail Analysis
- 基础 UI：Combobox multiple + Observable Plot + Tabs + Table
- fixture：注入 prototype-backed wafer ranking、CP matrix、loss yield、condition comparison 数据
- 本地状态：detail tabs 展示模式
- 外部业务状态：Stage / Step filter、过滤后的业务数据集、跨组件 wafer drilldown
