## Contract

`ReportYieldAnalysis` 展示 Yield Analysis tab 的三段式结构：

- 过滤区域使用 shadcn/base multiple combobox，Stage / Step 选择值通过 `onStageFilterChange`、`onStepFilterChange` 抛给外部业务状态。
- Wafer Yield & CP Fail Analysis 的绿色折线与 CP Fail 堆叠柱共享 0–100% 纵轴。Wafer 顺序、Condition、Step、Yield、CP Fail 百分比与 failed-die count 全部来自输入；图表仅展示 `percent > failThresholdPercent` 的 CP Fail，图例保持 `series` 输入顺序。
- Yield Detail Analysis 使用 shadcn/base tabs 切换 `Wafer x CP Matrix`、`Loss Yield`、`Condition Yield Comparison` 三张表。

图表 hover 和键盘 focus 都显示当前 Wafer 的 Yield 及通过阈值的 CP Fail 详情；pointer leave、blur、滚动、resize 或 `Escape` 关闭 tooltip。图表面板可独立收起，这些都是局部展示状态，不触发数据请求或跨组件 workflow。

筛选区使用无外框的紧凑控制行，只保留控件自身边界；组合图继续使用单层中性 Analytical Surface。明细分析使用无 Card 的轻量标题 / Tabs 工具栏，矩阵表以自身的边界和局部横向滚动作为唯一可读壳，不嵌套第二张分析卡片。组件内部只关心 report yield analysis schema 和本地展示状态；过滤后的业务数据由外部注入。

## Consumer handoff · POC

`onWaferSelect(waferId)` 表达 Matrix / Condition 表的 Wafer 下钻意图，路由与目标选择由 App 负责。
`input.focusedWaferId` 只定位并高亮该 Wafer，不删除其比较组或 Baseline。Matrix 以 `groupId` 合并分组信息；局部“组内按 Yield 排序”保持成员身份、Baseline 和组序不变，缺 Yield 排到组尾，恢复按钮使用输入成员顺序。

`stepOptions` 是 consumer 按已选 Stage 提供的范围，Stage 改变后无效 Step 的清理属于外部状态。
`goodDies` 独立承载冻结 GOOD 事实，Matrix 的 Good / Tested Dies 只读该字段；缺失显示 `—`。旧 `passDies` 是 SBIN PASS 事实，绝不作为 GOOD 的回退。
Baseline 的 NULL Delta 显示 `—`，非 Baseline 的比较对象或有效 Yield 缺失单独说明。失败率 0 显示 `—`，缺记录显示“缺少数据”，不能互换。

Matrix 在本地双向滚动区域保留表头；Loss 列名明确为 Cumulative Yield Loss。Condition 列顺序为 Stage / Step / Seq、Condition、Wafers、四类 Yield，公式及排序数据仍由 consumer 提供。
