## Contract

`ReportSplitTable` 是只读 report snapshot，不负责编辑 split、recipe 或 MES release。
组件由 `Wafer Yield & CP Fail Analysis`、过滤区域和逐 wafer 的 Split Table 组成；
过滤区域使用多选 Combobox 按 `stageOptions` / `stepOptions` 过滤，空选中表示 `全部`。

分析图的绿色折线与 CP Fail 堆叠柱共享 0–100% 纵轴；Wafer 顺序、Condition、Step、
Yield、CP Fail 百分比与 failed-die count 全部来自输入。图表严格只显示
`percent > failThresholdPercent` 的 CP Fail，默认阈值为 `2%`；图例仅列出通过阈值的
参数，并保持 `series` 输入顺序。组件不会从 fail count 或 Yield 推导业务事实。

图表 hover 和键盘 focus 都显示当前 Wafer 的 Yield 及通过阈值的 CP Fail 详情；
pointer leave、blur、滚动、resize 或 `Escape` 关闭 tooltip。图表面板可独立收起，这些
都是局部展示状态，不触发数据请求或跨组件 workflow。

表格按 `Stage + Step + Seq` 形成对照组并合并首列。每组先展示 Baseline，再按不同
`condition` 的首次出现顺序生成 `split-1`、`split-2` 等标签；同一 condition 的多个
Wafer 共享同一个 split 标签。表格投影固定为 `Stage / Step / Seq`、`Wafer ID`、
`Recipe`、`Condition`、`Yield` 与 `Top Fail` 六列。

`Top Fail` 直接消费 report snapshot 注入的 CP 参数与数量。`topFails` 有值时可展示
多个 `CP Parameter · Count`；未提供时兼容单值 `topFail` / `topFailCount`。组件不从
raw die data 推算阈值或 Top Fail，也不推断实际工艺事实。

过滤区使用紧凑 Analytical Surface；表格保持自己的单层中性边界与浅色结构表头，
不嵌入第二张 Card。较宽的业务投影通过组件自身的横向滚动容器展示，不能撑破 MDX
预览壳。

本轮表格组合参考本地原型 `DOE Workbench 单文件版.html` 的 `renderSplit`：只迁入
分组、Baseline-first、condition split 标签和多 CP Top Fail 展示；跨 Tab 导航仍由
App 通过 callback 承接。

## Consumer Schema

```ts
type ReportSplitTableInput = {
  yieldCpFailAnalysis?: {
    title: string
    failThresholdPercent: number
    series: Array<{ parameter: string }>
    wafers: Array<{
      waferId: string
      step: string
      condition: string
      yield: number
      cpFails: Array<{
        parameter: string
        failedDies: number
        percent: number
      }>
    }>
  }
  stageOptions?: string[]
  stepOptions?: string[]
  selectedStages?: string[]
  selectedSteps?: string[]
  rows?: ReportSplitTableRow[]
}
```

参考来源为本地 DOE Workbench 单文件版源码和用户提供的目标截图。归属经用户确认是
`Split Table`，不是 `Wafer Map`。详细证据与交互规则见
`docs/upstream/components/011-report-split-table/README.md`。
