## Contract

`WaferMapGallery` is the shared rendering entry point, not the Report Center tab entry
point. It accepts one resolved discriminated input: `cp-final-bin`, `cp-parameter`,
or `defect`. `ReportWaferMap` composes this Gallery for Report Center; DOE App must
not place a Gallery beside a separately reimplemented Report control bar. Every wafer
carries its own geometry and data payload; no fixture or component assumes that 25
wafers share values.

Final Bin presentation preserves the BFF bin label and supplied `die.pass` literally.
Explicit Pass uses a green colour family; explicit Fail uses a contrasting warm
colour family, with stable bin-specific shades. Neither numeric Bin `1`, a label,
nor a colour hash can override `die.pass`. The legacy input palette is a fallback
only when CP status is absent; the Final Bin schema requires that status. Thumbnail,
fullscreen and legend use the same resolver. Mixed-state bins show both swatches;
supplied inspection counts and summary facts remain unchanged.

All modes share a neutral grey legal-die base. Defect types use saturated contrasting
colours so selected defects remain visible against the base. Parameter legends in
the gallery and fullscreen show the supplied `scale.domainMin` / `domainMax` and unit,
using the same continuous value-to-colour function as the map. Grey means no valid
value; red outlines denote only explicitly supplied CP Fail. The component never
computes a new range, interprets the range as specification, or invents OOS cutoffs.

`WaferMapCore` owns three stacked Canvas layers: an immediate base layer for all legal dies, a data layer for Final Bin / parameter / defect color, and an interaction layer. The shallow grey circular boundary is presentation only; the supplied legal-die coordinates define the actual footprint.

CP geometry (`CP_DIE_GRID_V1`) and defect geometry (`DEFECT_INDEX_V1`) are independent coordinate contracts. This component deliberately does not infer an overlay between them.

Defect gallery uses single-select, searchable Combobox controls for `Layer` and `Defect Type`. `All Defect Type` serializes to an empty type filter, which means all defect types on the selected Layer.

Hover uses Canvas hit testing and one document portal tooltip, so a 4,099-die wafer never creates 4,099 React nodes. The tooltip currently shows wafer, DIE_X, DIE_Y, Final Bin and, where relevant, parameter value/validity or defect count.

每片 wafer 卡片提供 `全屏查看` 入口。放大层复用同一个 Canvas renderer，并拥有局部
Die 选择、80%–140% 缩放和前后 wafer 浏览；它不触发请求或改变外部筛选。右侧先展示
当前 Die 明细，再展示由输入合同提供的 wafer 统计表。三种视图分别使用 Final Bin、
CP × Defect 分类和按 Layer 的 Defect Type 统计，组件不会从缺失字段推断这些业务事实。

## Schema

```ts
export const waferMapDieSchema = z.object({
	id: z.string(),
	x: z.number().finite(),
	y: z.number().finite(),
})

export const waferMapBoundsSchema = z.object({
	minX: z.number().finite(),
	maxX: z.number().finite(),
	minY: z.number().finite(),
	maxY: z.number().finite(),
})

export const waferMapDataSchema = z.object({
	id: z.string(),
	dies: z.array(waferMapDieSchema),
	bounds: waferMapBoundsSchema,
})
```

可放大 wafer 的 expected schema 还要求 mode-specific `inspection`：

```ts
type FinalBinInspection = {
  testedDieCount: number
  totalFailBinCount: number
  totalFailBinRatePercent: number
  rows: Array<{ binCode: string; binDescription: string; count: number; ratePercent: number }>
}

type ParameterInspection = {
  testedDieCount: number
  rows: Array<{
    classification: "cp-fail-defect" | "cp-pass-defect" | "cp-pass-no-defect" | "cp-fail-no-defect"
    label: string
    count: number
    ratePercent: number
  }>
}

type DefectInspection = {
  byLayer: Array<{
    layerId: string
    defectDieCount: number
    defectRecordCount: number
    rows: Array<{ typeId: string; label: string; count: number; ratePercent: number }>
  }>
}
```

The gallery input extends this geometry with rendering-specific die metadata. The component owns the local expanded inspection view, but owns no data fetch, parameter percentile calculation, defect/statistics aggregation, or routing; those belong to the consuming app/BFF.

## Consumer missing-map presentation

`WaferMapGallery.renderMissingMap(state)` optionally supplies the body of an
explicitly empty or unavailable map slot. ReportWaferMap uses ReportState with
the source reason and 160px minimum height. Available/partial map rendering,
summary facts, standalone gallery fallbacks and data semantics remain intact.
