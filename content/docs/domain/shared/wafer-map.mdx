## Contract

`WaferMapGallery` is the business entry point. It accepts one discriminated input: `cp-final-bin`, `cp-parameter`, or `defect`. Every wafer carries its own geometry and its own data payload; no fixture or component assumes that 25 wafers share values.

`WaferMapCore` owns three stacked Canvas layers: an immediate base layer for all legal dies, a data layer for Final Bin / parameter / defect color, and an interaction layer. The shallow grey circular boundary is presentation only; the supplied legal-die coordinates define the actual footprint.

CP geometry (`CP_DIE_GRID_V1`) and defect geometry (`DEFECT_INDEX_V1`) are independent coordinate contracts. This component deliberately does not infer an overlay between them.

Defect gallery uses single-select, searchable Combobox controls for `Layer` and `Defect Type`. `All Defect Type` serializes to an empty type filter, which means all defect types on the selected Layer.

Hover uses Canvas hit testing and one document portal tooltip, so a 4,099-die wafer never creates 4,099 React nodes. The tooltip currently shows wafer, DIE_X, DIE_Y, Final Bin and, where relevant, parameter value/validity or defect count.

## Schema

```ts
export const waferMapDieSchema = z.object({
	id: z.string(),
	x: z.number().finite(),
	y: z.number().finite(),
})

export const waferMapBoundsSchema = z.object({
	minX: z.number().finite(),
	maxX: z.number().finite(),
	minY: z.number().finite(),
	maxY: z.number().finite(),
})

export const waferMapDataSchema = z.object({
	id: z.string(),
	dies: z.array(waferMapDieSchema),
	bounds: waferMapBoundsSchema,
})
```

The gallery input extends this geometry with rendering-specific die metadata. The component owns no data fetch, parameter percentile calculation, defect aggregation, routing, or detail view; those belong to the consuming app/BFF.
