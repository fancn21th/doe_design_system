# DOE Visual References

## How References Are Used

References are inputs to analyse, not sources to copy blindly. Record the
source, the extracted rule, what DOE adopts, and what DOE rejects in
`references/`. Promote only the distilled rule into this design system.

Use `docs/visual-system/extraction-process.md` for the required sequence from
evidence to a Foundation, Pattern, or Domain contract.

## Current Sources

| Source | Role | Authority |
| --- | --- | --- |
| Local `g-doe/ui` reference project | Primary implementation and composition reference when a user asks to adopt a named shadcn block | Follow the UI Reference Refactor SOP for fidelity; it is not DOE domain truth |
| shadcn dashboard templates | Visual-language evidence for enterprise layout, hierarchy, and component composition | Reference only |
| DOE upstream prototype records | Evidence for DOE data, local interaction, and domain composition | Domain-specific evidence |
| Fumadocs | Documentation rendering shell | No DOE product visual authority |

## Required Reference Record

Every reusable extraction records its source path or URL, observed visual
facts, accepted rules, rejected traits, and candidate promotion target. Use the
template-analysis directory for this record.
